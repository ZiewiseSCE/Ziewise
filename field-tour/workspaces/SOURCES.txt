Ziewise physical office workstations

Geometry, materials and content

The height-adjustable desks, routed veneer edges, operator chairs, five-wheel
bases, moulded keycaps, monitors and stands, glass partitions, folders,
document handling devices, USB accessories, stationery, camera fixture and
software instruments were modelled for the walkthrough. The glass desk
protectors sit on pads above the HR and finance worktops. The paper surfaces
have curled vertices, stacked edges, printed sample text and a paper normal.
The Korean interfaces, sample documents and demonstration records were
authored for this scene.

Three real-scale, seated, textured meshes by Innerscene use MakeHuman/MPFB
body and system assets. The source library and embedded GLB copyright notices
identify the models as CC0 1.0. The tour editions preserve the artists' posed
body, hands, clothing and material UVs. Their meshes were reduced for a web
walkthrough and their image maps resized. The original wooden chair was
removed from the coordinator model so the colleague can use this workspace's
ergonomic chair. Its hair and shirt colours were adjusted; its office shirt
includes the credited woven material below.

Integration

Install the contents as field-tour/workspaces/. The module uses the existing
field-tour/vendor/loaders/GLTFLoader.js with the renderer's Three.js. All
image and mesh references resolve within the workspaces directory.

Call buildWorkspace(T,id) for knowledge, hr, finance, purchase, sales, roi
and poc. Each returns group, three local Vector3 anchors, update(progress)
and ready. Call the existing batchStatic before adding to the world and await
ready before capturing a poster. The group is in metres and faces local +Z.
For each department the working surface is 0.757 m above the existing floor.

The knowledge station also returns setProvider(name). Accepted names are
local, gpt, claude and gemini, case-insensitive. The default and unknown
names select local. Selection updates the physical diagnostic display and
socket indicator. The four ports represent selectable configuration profiles
in an illustrative deployment. This function renders a configuration
example entirely on the client.
